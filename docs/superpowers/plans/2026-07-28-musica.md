# Módulo de música — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Meter Voidtify entero dentro de la app única como módulo `musica` bajo `/musica/`, con una sola base de datos, preservando las 271.769 reproducciones que viven en `C:\Voidtify`.

**Architecture:** Igual que `habitos`: el código va a `src/modules/musica/`, se expone por su `index.ts`, y `src/app/musica/` solo enruta. `auth.ts` sube a `src/modules/core/auth/`. El guard de sesión vive en `src/app/musica/layout.tsx`, así que hábitos y tareas quedan fuera por construcción.

**Tech Stack:** Next 16.2.12 · Drizzle 0.45 · Auth.js v5 (next-auth beta) · better-sqlite3 · Last.fm API · vitest 4.1

**Spec:** `docs/superpowers/specs/2026-07-28-musica-design.md`

## Antes de empezar: lee esto

**Aquí NO hay migración de ORM.** Voidtify ya usa Drizzle, con el mismo patrón de
singleton que `habitos`. A diferencia del sub-proyecto 1, no se reescribe ni una
consulta. El trabajo es mover archivos, reescribir rutas de import y copiar datos.
Si te encuentras reescribiendo una query, párate: te has salido del alcance.

**El dato es lo que importa.** 271.769 filas de historial de escucha, de 2018 a 2026,
importadas del volcado GDPR de Spotify. No se pueden volver a pedir a la API. Todo el
orden de este plan está pensado para que ese dato esté a salvo antes de tocar código.

**No escribas nunca en `C:\Voidtify`.** Se lee y se deja congelada. Es la red de
seguridad hasta que el usuario decida borrarla, y esa decisión no es de este plan.

**Next 16 no es el Next que crees conocer.** Consulta `node_modules/next/dist/docs/`
antes de escribir rutas, layouts o server actions.

**Diferencia de patrón entre módulos, a propósito.** En `habitos` la lógica vive en
`lib/mutations.ts` (recibe `db`) y `actions.ts` es un envoltorio `"use server"`. En
Voidtify, los 14 archivos con `"use server"` están repartidos por `lib/` y toman el
singleton directamente. **No lo unifiques**: son 14 archivos que refactorizar durante
una migración, justo lo que el spec prohíbe. Queda como deuda anotada.

```js
import Database from "better-sqlite3";

/**
 * Las cinco tablas con contenido real. `spotify_credentials` queda fuera a
 * propósito: son tokens de acceso que caducan y se regeneran al iniciar
 * sesión. Las otras seis tablas del esquema están vacías en origen.
 */
export const TABLAS_A_MIGRAR = [
  "streams",
  "import_batches",
  "artist_genres",
  "top_snapshots",
  "capture_state",
];

/**
 * Copia las tablas de `origen` a `destino` con ATTACH, en una transacción.
 *
 * `INSERT OR IGNORE` hace la operación idempotente: si la ejecutas dos veces,
 * las claves ya presentes se saltan en vez de duplicarse o reventar.
 *
 * El origen se abre en solo lectura. Esto es deliberado y no una precaución
 * decorativa: el origen es la única copia de ocho años de historial.
 */
export function copiarTablas(rutaOrigen, rutaDestino) {
  const db = new Database(rutaDestino);
  const conteos = {};
  try {
    db.pragma("foreign_keys = OFF");
    db.exec(`ATTACH DATABASE '${rutaOrigen.replace(/'/g, "''")}' AS origen`);
    const copiar = db.transaction(() => {
      for (const tabla of TABLAS_A_MIGRAR) {
        db.exec(`INSERT OR IGNORE INTO main."${tabla}" SELECT * FROM origen."${tabla}"`);
        conteos[tabla] = db
          .prepare(`SELECT count(*) c FROM main."${tabla}"`)
          .get().c;
      }
    });
    copiar();
    return conteos;
  } finally {
    try {
      db.exec("DETACH DATABASE origen");
    } catch {
      // Si el ATTACH falló, no hay nada que soltar.
    }
    db.pragma("foreign_keys = ON");
    db.close();
  }
}

/** Conteos de las tablas a migrar en una base, para verificar antes/después. */
export function contar(ruta) {
  const db = new Database(ruta, { readonly: true });
  try {
    const out = {};
    for (const tabla of TABLAS_A_MIGRAR) {
      out[tabla] = db.prepare(`SELECT count(*) c FROM "${tabla}"`).get().c;
    }
    return out;
  } finally {
    db.close();
  }
}
```
